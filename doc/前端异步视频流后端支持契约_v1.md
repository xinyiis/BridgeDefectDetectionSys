# 前端异步视频流后端支持契约 v1

## 1. 文档定位

本文档只定义后端协议行为与可观测结果，不约束前端实现方式。  
前端可自行决定页面、状态管理、组件与交互实现。

## 2. 接口清单

1. `POST /api/v1/detection/video/upload`
2. `POST /api/v1/detection/video/{task_id}/start`
3. `GET /api/v1/detection/video/{task_id}`
4. `POST /api/v1/detection/video/{task_id}/cancel`
5. `GET /api/v1/detection/video/ws?task_id={task_id}&session_id={session_id}`

## 3. WebSocket 事件

固定事件类型：

1. `connected`
2. `frame`
3. `progress`
4. `completed`
5. `error`

## 4. 一致性规则（必须遵守）

1. HTTP 任务状态是最终真相源。
2. WS 是实时增量通知，不作为最终一致性依据。
3. 断连、乱序、重复消息后，应通过 `GET /api/v1/detection/video/{task_id}` 收敛状态。
4. `completed`/`error` 是终止事件；终止后增量消息可忽略。

## 5. 超时与错误语义

1. queued 超时：`等待算法 queued 回调超时`
2. queued 后无进度超时：`queued 后连续无进度消息超时`

前端建议直接展示 message 原文，避免语义丢失。

## 6. cancel 竞态语义

1. 若 cancel 已成功落库，任务最终状态必须保持 `canceled`。
2. 晚到 `frame/progress/completed` 不得覆写 `canceled`。
3. 若任务已终态（`completed/failed/canceled`），cancel 不应改变终态。

## 7. 字段级约束

完整字段规范、可空规则、默认值、单位与 unknown-field 策略以 SoT 为准：  
`.omx/contracts/video-async/v1/contract.yaml`

## 8. 联调验收最小集

1. 正常链路完成（upload -> start -> ws -> completed）
2. queued 超时触发 error
3. queued 后无进度超时触发 error
4. cancel 竞态最终状态正确
