# 图像检测接口改造设计文档

## 1. 背景与目标
目前后端的图像缺陷检测模块（`DetectionUseCase.UploadAndDetect`）与真实的算法中台接口（基于《算法接口文档.md》）存在严重的不匹配。后端假设了一个一次性的 JSON 接口，而算法中台实际上是一个基于 `multipart/form-data` 的多阶段流水线。
目标是重构后端的 HTTP Python Service 和 UseCase 逻辑，使其正确对接算法中台的三段式处理（检测+分割），同时保持领域模型的干净。

## 2. 问题分析与现状

- **接口协议不匹配**：当前 `HTTPPythonService.DetectDefect` 发送的是 JSON 数据，而算法需要 `multipart/form-data`。
- **流程不匹配**：当前代码只做了一次 HTTP 请求。真实的流程应该是：调用 `/algo/detect` 获取边界框 (BBox) -> 将 BBox JSON 化 -> 调用 `/algo/segment` 获取带 Mask 的融合图。
- **坐标系不匹配**：Python 服务返回的是 YOLO 归一化坐标 (`[x_center, y_center, w_ratio, h_ratio]`)，而后端入库需要真实的物理尺寸和像素框坐标。`CalculatePhysicalDimensions` 函数已被定义但未被应用。
- **缺少图像尺寸上下文**：因为计算真实物理面积需要 `原图宽` 和 `原图高`，当前 `DetectionUseCase` 保存了文件但没有提取尺寸。

## 3. 重构方案

本次改造严格遵循现有架构的层次结构，主要涉及 `infrastructure` (外部服务适配) 和 `application` (用例编排) 两层。

### 3.1 基础设施层：重构 `HTTPPythonService`

在 `src/backend/internal/infrastructure/external/python_service_http.go` 中，修改 `DetectDefect` 方法作为高级封装：

1. **组合调用逻辑**：
   - 先调用现有的 `s.Detect(imagePath, ...)`，使用 `modelName` 和默认置信度(可设为0.25)。
   - 如果 `yolo_bboxes` 为空，直接组装空结果返回（没有缺陷）。
   - 如果不为空，将 `yolo_bboxes` 序列化为 JSON 字符串。
   - 调用 `s.Segment(imagePath, ...)`。
2. **数据映射**：
   - 将 `DetectResult` 和 `SegmentResult` 的数据映射回统一的 `service.PythonDetectionResult` 结构。
   - `DefectDetection.DefectType` 取 `BBoxItem.ClassName`。
   - 将归一化坐标原封不动存入 `BBoxData`（虽然 `BBoxData` 现在的定义是 `int` 像素，建议直接将归一化数据传给上一层，由 UseCase 结合图片尺寸来处理，或者直接修改 `BBoxData` 接收 float64 归一化坐标）。
   - 将 `SegmentResult.FusionImage` (Base64) 作为 `ResultImage`。

### 3.2 领域层：更新 `BBoxData` 数据结构

修改 `src/backend/internal/domain/service/python_service.go`：
当前的 `BBoxData` 是为像素准备的：
```go
type BBoxData struct {
    X      int `json:"x"`
    Y      int `json:"y"`
    Width  int `json:"width"`
    Height int `json:"height"`
}
```
**改动：** 增加原始 YOLO 归一化坐标数组字段，供上层换算。
```go
type BBoxData struct {
    // 真实的像素坐标（将在 UseCase 阶段填充）
    X      int `json:"x"`
    Y      int `json:"y"`
    Width  int `json:"width"`
    Height int `json:"height"`
    // 算法原始返回的归一化坐标 [x_center, y_center, width, height]
    YOLOCoords [4]float64 `json:"yolo_coords"` 
}
```

### 3.3 应用层：重构 `DetectionUseCase.UploadAndDetect`

修改 `src/backend/internal/application/usecase/detection_usecase.go`：

1. **提取图像尺寸**：
   在读取图片保存到本地后（`uc.fileService.SaveImage`），使用 `image.DecodeConfig` 获取原图的宽度(`imgW`)和高度(`imgH`)。
2. **调用服务与坐标转换**：
   调用重构后的 `uc.pythonService.DetectDefect` 获得结果。
   在遍历结果生成 `model.Defect` 实体时，引入物理尺寸计算逻辑：
   ```go
   // 调用已经存在的函数
   x, y, w, h, length, width, area := service.CalculatePhysicalDimensions(
       detectedDefect.BBox.YOLOCoords,
       imgW, imgH,
       req.PixelRatio,
   )
   
   // 修正当前 defect 的 BBox 信息
   detectedDefect.BBox.X = x
   detectedDefect.BBox.Y = y
   // ...
   ```
3. **中文映射**：
   算法返回的 `DefectType` 是英文字符串（如 `"Crack"`），利用 `service.ClassNameToChinese` 或者通过映射将其入库前转为标准中文描述。
4. **ResultImage 保存**：
   现在的逻辑中已经有了将 Base64 保存为文件的逻辑（`uc.fileService.SaveResultImage`），保持不变。
